Nos dois capítulos anteriores, introduzimos o transformer e vimos como pré-treinar um modelo de linguagem transformer como um modelo de linguagem causal ou da esquerda para a direita. Neste capítulo, introduziremos um segundo paradigma para modelos de linguagem pré-treinados, o codificador transformer bidirecional, e a versão mais amplamente utilizada, a família de modelos BERT (Devlin et al., 2019). Este modelo é treinado via modelagem de linguagem mascarada, onde, em vez de prever a palavra seguinte, mascaramos uma palavra no meio e pedimos ao modelo para adivinhar a palavra dadas as palavras de ambos os lados. Este método permite, assim, que o modelo veja o contexto direito e esquerdo.

*fine-tuning*aprendizado por transferência

Também introduzimos o fine-tuning no capítulo anterior. Aqui descrevemos um novo tipo de fine-tuning, no qual pegamos a rede transformer aprendida por esses modelos pré-treinados, adicionamos um classificador de rede neural após a camada superior da rede e o treinamos em alguns dados rotulados adicionais para realizar alguma tarefa a jusante, como rotulagem de entidades nomeadas ou inferência de linguagem natural. Como antes, a intuição é que a fase de pré-treinamento aprende um modelo de linguagem que instancia representações ricas de significado de palavras, o que permite que o modelo aprenda mais facilmente («seja fine-tuned para») os requisitos de uma tarefa de compreensão de linguagem a jusante. Este aspecto do paradigma pré-treinamento-fine-tuning é uma instância do que é chamado de transfer learning em aprendizado de máquina: o método de adquirir conhecimento de uma tarefa ou domínio e, em seguida, aplicá-lo (transferi-lo) para resolver uma nova tarefa.

9.1 Três arquiteturas para modelos de linguagem

A arquitetura que descrevemos no Capítulo 7 para um modelo de linguagem autorregressivo da esquerda para a direita é, na verdade, apenas uma das três arquiteturas comuns de LM.

As três arquiteturas são o codificador, o decodificador e o codificador-decodificador. A Fig. 9.1 apresenta uma imagem esquemática das três.

decodificador

O decodificador é a arquitetura que introduzimos anteriormente. Ele recebe como entrada uma série de tokens e gera iterativamente um token de saída por vez. O decodificador é a arquitetura usada para criar grandes modelos de linguagem como GPT, Claude, Llama e Mistral. O fluxo de informação nos decodificadores vai da esquerda para a direita, o que significa que o modelo prevê a próxima palavra apenas a partir das palavras anteriores. Os decodificadores são modelos generativos, o que significa que, dados tokens de entrada, eles geram novos tokens de saída.

codificador

O codificador recebe como entrada uma sequência de tokens e produz uma representação vetorial para cada token. Os codificadores são geralmente modelos de linguagem mascarados, o que significa que são treinados mascarando uma palavra e aprendendo a predi-lá olhando para as palavras circundantes em ambos os lados. Modelos de linguagem mascarados como BERT, RoBERTA e outros da família BERT são modelos codificadores. Os modelos codificadores não são modelos generativos; eles não são usados para gerar texto. Em vez disso, os modelos codificadores são frequentemente usados para

codificador-decodificador

criar classificadores, por exemplo, onde a entrada é texto e a saída é um rótulo, por exemplo, para sentimento ou tópico ou outras classes. Isso é feito ajustando-os (treinando-os em dados supervisionados). Introduziremos modelos codificadores neste capítulo.

Ocodificador-decodificador recebe como entrada uma sequência de tokens e produz uma série de tokens. O que o diferencia dos modelos apenas decodificadores é que um codificador-decodificador tem uma relação muito mais solta entre os tokens de entrada e os tokens de saída, e eles são usados para mapear entre diferentes tipos de tokens. Ou seja, em um codificador-decodificador, os tokens de saída podem ser de um conjunto de tokens muito diferente ou ser uma sequência muito mais longa ou mais curta do que a sequência de tokens de entrada. Por exemplo, arquiteturas codificador-decodificador são usadas para tradução automática, onde os tokens de entrada estão em um idioma e os tokens de saída (provavelmente mais ou menos) estão em outro idioma. Arquiteturas codificador-decodificador também são usadas para reconhecimento de fala, onde a entrada são tokens que representam fala e a saída são tokens que representam texto. Introduziremos a arquitetura codificador-decodificador para tradução automática no Capítulo 13 e para reconhecimento de fala no Capítulo 16.

Essas três arquiteturas podem ser construídas a partir de muitos tipos de redes neurais, mas continuaremos a assumir aqui o uso do transformer.

9.2 Codificadores Transformer Bidirecionais

Vamos começar introduzindo o codificador transformer bidirecional que fundamenta modelos como BERT e seus descendentes comoRoBERTa (Liu et al., 2019). A natureza da esquerda para a direita dos LLMs decodificadores do Capítulo 7 pode ser uma limitação, porque existem tarefas para as quais seria útil, ao processar um token, poder ver os tokens futuros. Isso é especialmente verdadeiro para tarefas derotulagem de sequências nas quais queremos rotular cada token com um rótulo, como a tarefa derotulagem de entidades nomeadas que introduziremos na Seção 9.5, ou tarefas como rotulagem de classe gramatical ou análise sintática que aparecem em capítulos posteriores.

Os codificadoresbidirecionais que introduzimos aqui são um tipo diferente de modelo dos modelos causais. Os modelos causais do Capítulo 7 são modelos generativos, projetados para gerar facilmente o próximo token em uma sequência. Mas o foco dos codificadores bidirecionais é, em vez disso, computar representações contextualizadas dos tokens de entrada. Os codificadores bidirecionais usam autoatenção para mapear sequências de embeddings de entrada (x1,...,xn) para sequências de embeddings de saída do mesmo comprimento (h1,...,hn), onde os vetores de saída foram contextualizados usando informações de toda a sequência de entrada. Esses embeddings de saída são representações contextualizadas de cada token de entrada que são úteis em uma variedade de aplicações onde precisamos fazer uma classificação ou uma decisão com base no token no contexto.

Lembrem-se de que dissemos que os modelos do Capítulo 7 são às vezes chamados deapenas decodificadores, porque correspondem à parte decodificadora do modelo codificador-decodificador que introduziremos no Capítulo 13. Em contraste, os modelos de linguagem mascarados deste capítulo são às vezes chamados deapenas codificadores, porque produzem uma codificação para cada token de entrada, mas geralmente não são usados para produzir texto corrido por decodificação/amostragem. Embora seja possível usar modelos de linguagem mascarados para algumas tarefas de geração, por exemplo, em trabalhos recentes envolvendo difusão, não discutimos isso aqui ainda. Focaremos no uso de modelos de linguagem mascarados para tarefas interpretativas.

9.3 Treinando Codificadores Bidirecionais

tarefa *cloze*

Treinamos modelos de linguagem transformer causais no Capítulo 7 fazendo-os prever iterativamente a próxima palavra em um texto. Mas eliminar a máscara causal na atenção torna a tarefa de modelagem de linguagem de adivinhar a próxima palavra trivial — a resposta está diretamente disponível no contexto —, então precisamos de um novo esquema de treinamento. Em vez de tentar prever a próxima palavra, o modelo aprende a realizar uma tarefa de preenchimento de lacunas, tecnicamente chamada de tarefa cloze (Taylor, 1953). Para ver isso, vamos retornar ao exemplo motivador do Capítulo 3. Em vez de prever quais palavras provavelmente virão a seguir neste exemplo:

The water of Walden Pond is so beautifully [em português: A água do Lago Walden é tão lindamente]

somos solicitados a prever um item ausente dado o restante da frase.

The of Walden Pond is so beautifully ... [em português: O de Walden Pond é tão lindamente ...]

Ou seja, dado uma sequência de entrada com um ou mais elementos ausentes, a tarefa de aprendizado é prever os elementos ausentes. Mais precisamente, durante o treinamento, o modelo é privado de um ou mais tokens de uma sequência de entrada e deve gerar uma distribuição de probabilidade sobre o vocabulário para cada um dos itens ausentes. Em seguida, usamos a função de perda de entropia cruzada de cada uma das previsões do modelo para impulsionar o processo de aprendizado.

desruído

Essa abordagem pode ser generalizada para qualquer um de uma variedade de métodos que corrompem a entrada de treinamento e depois pedem ao modelo para recuperar a entrada original. Exemplos dos tipos de manipulações que foram usadas incluem máscaras, substituições, reordenações, exclusões e inserções estranhas no texto de treinamento. O nome geral para esse tipo de treinamento é chamado de denoising: corrompemos (adicionamos ruído ao) input de alguma forma (mascarando uma palavra ou colocando uma palavra incorreta) e o objetivo do sistema é remover o ruído.

9.3.1 Palavras Mascaradas

Modelagem de Linguagem Mascarada

Descrevemos a abordagem de Masked Language Modeling (MLM) para treinar codificadores bidirecionais (Devlin et al., 2019). Assim como nos métodos de treinamento de modelo de linguagem que já vimos, MLM usa texto não anotado de um grande corpus. No treinamento MLM, o modelo é apresentado a uma série de frases do corpus de treinamento nas quais uma porcentagem de tokens (15% no modelo BERT) foi escolhida aleatoriamente para ser manipulada pelo procedimento de mascaramento. Dado uma frase de entrada lunch was delicious e assumindo que escolhemos aleatoriamente o 3º token delicious para ser manipulado,

• 80% das vezes: O token é substituído pelo token especial do vocabulário

named [MASK], e.g. lunch was delicious →lunch was [MASK].

• 10% das vezes: O token é substituído por outro token, amostrado aleatoriamente

do vocabulário com base nas probabilidades unigramas do token. ex. lunch was

delicious →lunch was gasp. [em português: delicioso → almoço foi ofegar.]

• 10% das vezes: o token permanece inalterado. ex. lunch was delicious

→lunch was delicious. [em português: o almoço estava delicioso.]

Em seguida, treinamos o modelo para adivinhar o token correto para os tokens manipulados. Por que as três manipulações possíveis? Adicionar o token [MASK] cria uma incompatibilidade entre pré-treinamento e ajuste fino ou inferência a jusante, pois quando empregamos o modelo MLM para realizar uma tarefa a jusante, não usamos nenhum token [MASK]. Se apenas substituíssemos tokens por [MASK], o modelo poderia prever tokens apenas quando visse um [MASK], mas queremos que o modelo tente sempre prever o token de entrada.

Para treinar o modelo a fazer a previsão, a sequência de entrada original é tokenizada usando um modelo de subword e os tokens são amostrados para serem manipulados. Os word embeddings para todos os tokens na entrada são recuperados da matriz de embedding E e combinados com embeddings posicionais para formar a entrada do transformer, passada através da pilha de blocos transformer bidirecionais, e então a cabeça de modelagem de linguagem. O objetivo de treinamento MLM é prever as entradas originais para cada um dos tokens mascarados e a função de perda de entropia cruzada dessas previsões impulsiona o processo de treinamento para todos os parâmetros no modelo. Ou seja, todos os tokens de entrada desempenham um papel no processo de autoatenção, mas apenas os tokens amostrados são usados para aprendizado.

9.3.2 Predição da Próxima Sentença

O foco do aprendizado baseado em máscara é prever palavras a partir de contextos circundantes com o objetivo de produzir representações eficazes em nível de palavra. No entanto, uma classe importante de aplicações envolve determinar a relação entre pares de frases. Estas incluem tarefas como detecção de paráfrase (detectar se duas frases têm significados semelhantes), inferência (detectar se os significados de duas frases implicam ou contradizem um ao outro) ou coerência do discurso (decidir se duas frases vizinhas formam um discurso coerente).

Predição da Próxima Sentença

Para capturar o tipo de conhecimento necessário para aplicações como estas, alguns modelos da família BERT incluem um segundo objetivo de aprendizado chamado Previsão da Próxima Sentença (NSP). Nesta tarefa, o modelo é apresentado a pares de sentenças e é solicitado a prever se cada par consiste em um par real de sentenças adjacentes do corpus de treinamento ou um par de sentenças não relacionadas. No BERT, 50% dos pares de treinamento consistiam em pares positivos, e nos outros 50% a segunda sentença de um par era selecionada aleatoriamente de outro lugar no corpus. A função de perda NSP é baseada em quão bem o modelo consegue distinguir pares verdadeiros de pares aleatórios.

Para facilitar o treinamento NSP, o BERT introduz dois tokens especiais na representação de entrada (tokens que também serão úteis para o fine-tuning). Após a tokenização da entrada com o modelo subword, o token [CLS] é prefixado ao par de sentenças de entrada, e o token [SEP] é colocado entre as sentenças e após o token final da segunda sentença. Na verdade, existem mais dois tokens especiais, um token de ‘Primeiro Segmento’ e um token de ‘Segundo Segmento’. Esses tokens são adicionados na fase de entrada aos embeddings de palavra e de posição. Ou seja, cada token da entrada X é na verdade formado pela soma de 3 embeddings: palavra, posição e embeddings de primeiro/segundo segmento.

Durante o treinamento, o vetor de saída hLCLS da camada final associada ao token [CLS] representa a previsão da próxima sentença. 9.3.3 Regimes de Treinamento

O BERT e outros modelos de linguagem baseados em transformer iniciais foram treinados em cerca de 3,3 bilhões de palavras (uma combinação da Wikipedia em inglês e um corpus de textos de livros chamado BooksCorpus (Zhu et al., 2015) que não é mais usado por razões de propriedade intelectual). Modelos de linguagem mascarados modernos são agora treinados em conjuntos de dados muito maiores de texto da web, filtrados um pouco e aumentados por dados de maior qualidade, como a Wikipedia, assim como aqueles que discutimos para os grandes modelos de linguagem causais do Capítulo 7. Modelos multilíngues usam de forma semelhante texto da web e Wikipedia multilíngue. Por exemplo, o modelo XLM-R foi treinado em cerca de 300 bilhões de tokens em 100 idiomas, retirados da web via Common Crawl (https://commoncrawl.org/).

Para treinar os modelos BERT originais, pares de segmentos de texto foram selecionados do corpus de treinamento de acordo com o esquema de 50/50 de previsão da próxima sentença. Os pares foram amostrados de modo que seu comprimento combinado fosse inferior a 512 tokens de entrada. Os tokens dentro desses pares de sentenças foram então mascarados usando a abordagem MLM com a função de perda combinada dos objetivos MLM e NSP usada para uma função de perda final. Como essa função de perda final é retropropagada através de todo o transformer, os embeddings em cada camada do transformer aprenderão representações que são úteis para prever palavras a partir de seus vizinhos. Como os tokens [CLS] são a entrada direta para o classificador NSP, suas representações aprendidas tenderão a conter informações sobre a sequência como um todo. Aproximadamente 40 passagens (épocas) sobre os dados de treinamento foram necessárias para o modelo convergir.

Alguns modelos, como o modelo RoBERTa, descartam o objetivo de previsão da próxima sentença e, portanto, alteram um pouco o regime de treinamento. Em vez de amostrar pares de sentenças, a entrada é simplesmente uma série de sentenças contíguas, ainda começando com o token especial [CLS]. Se o documento acabar antes de serem alcançados 512 tokens, um token separador extra é adicionado e sentenças do próximo documento são empacotadas, até que alcancemos um total de 512 tokens. Geralmente são usados tamanhos de lote grandes, entre 8K e 32K tokens.

Modelos multilíngues têm uma decisão adicional a tomar: qual dado usar para construir o vocabulário? Lembramos que todos os modelos de linguagem usam tokenização subword (BPE ou SentencePiece Unigram LM são os dois algoritmos mais comuns). Que texto deve ser usado para aprender essa tokenização multilíngue, dado que é mais fácil obter muito mais texto em alguns idiomas do que em outros? Uma opção seria criar esse conjunto de dados de aprendizado de vocabulário amostrando sentenças de nossos dados de treinamento (talvez texto da web do Common Crawl), aleatoriamente. Nesse caso, escolheremos muitas sentenças de idiomas com muita representação na web, como o inglês, e os tokens serão enviesados em direção a tokens raros em inglês em vez de criar tokens frequentes a partir de idiomas com menos dados. Em vez disso, é comum dividir os dados de treinamento em subcorpora de N idiomas diferentes, calcular o número de sentenças ni de cada idioma i, e reajustar essas probabilidades para aumentar o peso da probabilidade de idiomas menos representados (Lample and Conneau, 2019). Para muitos propósitos, um modelo multilíngue pré-treinado é mais prático do que um modelo monolíngue, pois evita a necessidade de construir muitos (cem!) modelos monolíngues separados. E os modelos multilíngues podem melhorar o desempenho em idiomas com poucos recursos aproveitando informações linguísticas de um idioma semelhante nos dados de treinamento que por acaso tem mais recursos. Não obstante, quando o número de idiomas cresce muito, os modelos multilíngues exibem o que tem sido chamado de maldição da multilinguidade (Conneau et al., 2020): o desempenho em cada idioma degrada em comparação com um modelo treinado em menos idiomas. Outro problema com modelos multilíngues é que eles ‘têm um sotaque’: estruturas gramaticais em idiomas de maior recurso (frequentemente inglês) vazam para idiomas de menor recurso; a vasta quantidade de idioma inglês no treinamento torna as representações do modelo para idiomas de baixo recurso ligeiramente mais parecidas com o inglês (Papadimitriou et al., 2023).

9.4 Fine-Tuning para Classificação

O poder dos modelos de linguagem pré-treinados reside em sua capacidade de extrair generalizações de grandes quantidades de texto — generalizações que são úteis para uma miríade de aplicações a jusante. Existem duas maneiras de fazer uso prático das generalizações para resolver tarefas a jusante. A maneira mais comum é usar linguagem natural para prompt o modelo, colocando-o em um estado onde ele gera contextualmente o que queremos.

fine-tuning

Nesta seção, exploramos uma maneira alternativa de usar modelos de linguagem pré-treinados para aplicações de baixo nível, um tipo de fine-tuning. No tipo de fine-tuning usado para modelos de linguagem mascarados, adicionamos circuitos específicos da aplicação (frequentemente chamados de head) sobre os modelos pré-treinados, tomando sua saída como entrada. O processo de fine-tuning consiste em usar dados rotulados sobre a aplicação para treinar esses parâmetros adicionais específicos da aplicação. Tipicamente, este treinamento irá congelar ou fazer apenas ajustes mínimos nos parâmetros do modelo de linguagem pré-treinado.

As seções seguintes introduzem métodos de fine-tuning para algumas classes comuns de aplicações baseadas em texto: classificação de sequências, classificação de pares de sentenças e rotulagem de sequências.

9.4.1 Classificação de Sequência

A tarefa de sequence classification é classificar uma sequência inteira de texto com um único rótulo. Este conjunto de tarefas é comumente chamado de text classification, como análise de sentimento ou detecção de spam (Apêndice B), em que classificamos um texto em duas ou três classes (como positivo ou negativo), bem como tarefas de classificação com um grande número de categorias, como classificação de tópicos em nível de documento.

cabeça de classificador

Para classificação de sequências, representamos toda a entrada a ser classificada por um único vetor. Podemos representar uma sequência de várias maneiras. Uma maneira é pegar a soma ou a média do último vetor de saída de cada token na sequência. Para o BERT, em vez disso, adicionamos um novo token único ao vocabulário chamado [CLS], e o antepomos ao início de todas as sequências de entrada, tanto durante o pré-treinamento quanto na codificação. O vetor de saída na camada final do modelo para a entrada [CLS] representa toda a sequência de entrada e serve como entrada para um classifier head, um classificador de regressão logística ou rede neural que toma a decisão relevante.

Como exemplo, vamos retornar ao problema de classificação de sentimento. O fine-tuning de um classificador para esta aplicação envolve aprender um conjunto de pesos, WC, para mapear o vetor de saída para o token [CLS] — hLCLS — para um conjunto de pontuações sobre as possíveis classes de sentimento. Assumindo uma tarefa de classificação de sentimento de três vias (positivo, negativo, neutro) e dimensionalidade d como a dimensão do modelo, WC terá o tamanho [d ×3]. Para classificar um documento, passamos o texto de entrada pelo modelo de linguagem pré-treinado para gerar hLCLS, multiplicamos por WC e passamos o vetor resultante por um softmax.

O fine-tuning dos valores em WC requer dados de treinamento supervisionado consistindo em sequências de entrada rotuladas com a classe de sentimento apropriada. O treinamento prossegue da maneira usual; a função de perda de entropia cruzada entre a saída softmax e a resposta correta é usada para impulsionar o aprendizado que produz WC.

Esta perda pode ser usada não apenas para aprender os pesos do classificador, mas também para atualizar os pesos do próprio modelo de linguagem pré-treinado. Na prática, um desempenho de classificação razoável é tipicamente alcançado com apenas mudanças mínimas nos parâmetros do modelo de linguagem, frequentemente limitadas a atualizações nas últimas poucas camadas do transformer. 9.4.2 Classificação de Pares de Sequência

Como mencionado na Seção 9.3.2, um tipo importante de problema envolve a classificação de pares de sequências de entrada. Aplicações práticas que se enquadram nesta classe incluem detecção de paráfrase (as duas sentenças são paráfrases uma da outra?), inferência lógica (a sentença A infere logicamente a sentença B?), e coerência de discurso (quão coerente é a sentença B como continuação da sentença A?).

inferência de linguagem natural

Como exemplo, vamos considerar uma tarefa de classificação de inferência com o conjunto de dados Multi-Genre Natural Language Inference (MultiNLI) (Williams et al., 2018). Na tarefa de inferência em linguagem natural ou NLI, também chamada de reconhecimento textual de inferência, um modelo é apresentado a um par de sentenças e deve classificar a relação entre seus significados. Por exemplo, no corpus MultiNLI, pares de sentenças são dados com um dos 3 rótulos: implica, contradiz e neutro. Esses rótulos descrevem uma relação entre o significado da primeira sentença (a premissa) e o significado da segunda sentença (a hipótese). Aqui estão exemplos representativos de cada classe do corpus:

• Neutral

a: Jon voltou para a cidade até a ferraria.

b: Jon viajou de volta para sua cidade natal.

• Contradicts

a: Os escritórios de Informação Turística podem ser muito úteis.

b: Os escritórios de Informação Turística nunca são de qualquer ajuda.

• Entails

a: Estou confuso.

b: Nem tudo é muito claro para mim. Uma relação de contradiz significa que a premissa contradiz a hipótese; implica significa que a premissa implica a hipótese; neutro significa que nenhum é necessariamente verdadeiro. O significado desses rótulos é mais flexível do que a inferência ou contradição lógica estrita, indicando que uma leitura típica humana das sentenças provavelmente interpretaria os significados dessa maneira.

Para fazer fine-tuning de um classificador para a tarefa MultiNLI, passamos os pares premissa/hipótese por um codificador bidirecional, conforme descrito acima, e usamos o vetor de saída para o token [CLS] como entrada para a cabeça de classificação. Assim como na classificação de sequências comum, esta cabeça fornece a entrada para um classificador de três vias que pode ser treinado no conjunto de treinamento MultiNLI.
